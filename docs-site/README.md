# PySM Starlight documentation site

Starlight (Astro) documentation site for PySM, deployed to GitHub Pages at
<https://galsci.github.io/pysm/>.

This is the experimental site; the canonical documentation remains on
Read the Docs at <https://pysm3.readthedocs.io/>.

## Commands

```bash
npm install              # install dependencies
npm run dev              # generate notebooks and archived versions, then start the dev server
npm run build            # generate notebooks and archived versions, then build to dist/
npm run generate:notebooks   # regenerate notebook pages from ../docs/*.ipynb
npm run generate:versions    # regenerate archived versions (3-4-4/3-4-5/3-4-6) from the git tags
```

Both `dev` and `build` run the generators first; the generated content is
gitignored and never committed. `generate:versions` requires the version git
tags to be available in the checkout (`git fetch --tags`) and `uvx` on PATH.

The production build is driven by `.github/workflows/docs-pages.yml`: it builds
`main` with base `/pysm/` and every open PR that contains `docs-site/` with base
`/pysm/preview/pr-<n>/`, then deploys a single artifact and posts a preview
comment on the PR.

## Environment variables

| Variable    | Default                            | Used for                         |
| ----------- | ---------------------------------- | -------------------------------- |
| `DOCS_SITE` | `https://galsci.github.io/pysm`    | Astro `site`                     |
| `DOCS_BASE` | `/pysm/`                           | Astro `base` (e.g. `/pysm/preview/pr-278/`) |

## Content

- `src/content/docs/` is the current (latest) documentation.
- `src/content/docs/notebooks/` is generated from `../docs/*.ipynb` (Git LFS) by
  `scripts/generate-notebooks.mjs`; it is gitignored and never committed.
- Archived versions are generated by `scripts/generate-versions.mjs` from the
  git tags of the repository: each tag's `docs/` (ReStructuredText) is converted
  to Markdown with `rst-to-myst`, its images and data files are copied, and the
  version sidebar is written to `src/content/versions/<version>.json`. Nothing
  is committed: the output lives in `src/content/docs/<version>/`,
  `src/content/versions/` and `.build/<version>/` (all gitignored).
- The per-version API reference is built by `starlight-pydocs` at build time
  from each tag's `src/` extracted into `.build/<version>/pysm3`; no API dumps
  are committed (legacy `dumps/` was removed for this reason).

To archive a new version: add it to `versions` in `astro.config.mjs` and to the
`versions` array in `scripts/generate-versions.mjs`, then run
`npm run generate:versions`.

## Notes

- Version slugs must not contain dots: Astro strips them from route slugs
  (the display label in the picker can still contain dots).
- LaTeX math is rendered with KaTeX via a `unified` markdown processor
  (`remark-math` + `rehype-katex`), which requires `@astrojs/markdown-remark`.
